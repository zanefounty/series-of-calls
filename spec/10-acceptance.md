## Full acceptance requirements

Each assessed scenario must include a reference solution, at least one different valid solution where the contract permits alternatives, and failures that isolate its important constraints. Fault injection should produce diagnosable state rather than merely subtract a score. Repair must prove recovery through the same workflow the learner uses.

Required incident classes include lost CRM context, stale workforce forecast, missing language skill, handoff loops, callback failure, identity mismatch after migration, inaccessible recordings, broken room calendars, retired offers, failed interconnects, one-way media, capacity exhaustion, prohibited processor/export, local service with external dependency, shared physical failure domains and support-chain gaps.

Achievements must name their observation window and required evidence. A successful one-off call is not a month of service continuity. A zero-cost sandbox cannot earn an economic sustainability achievement. Completion checks use outcomes and constraints, not exact reference configuration equality. Cost limits and allowed alternatives must be inspectable before submission.

## Browser and platform acceptance

Real browsers must exercise desktop and mobile portrait/landscape consoles, topology selection, inspector, keyboard focus, save/import/export, concurrent-tab ownership, worker error/staleness, backgrounding and offline reload under the project path. DOM tests cannot establish layout or service-worker correctness. The Playwright script serves the compiled project path, checks all optional consoles, keyboard topology selection, save/import/export, tab ownership and real service-worker offline reload across desktop and mobile portrait/landscape viewports. Full scenario acceptance remains separate. It must run successfully before browser evidence is claimed.

The current environment's execution sandbox denied Chromium crash-reporter/socket operations and WSLg display connections. Both full Chromium and its separate headless shell were attempted. This is a recorded infrastructure blocker, not a browser pass. No screenshot or offline result is fabricated.

## Gate abuse tests

Negative tests remove a source mapping and requirement together, change preserved source bytes, delete evidence, assert completion without implementation, create invalid catalogue edges, delete upstream commit accounting, expire a successful check and expire a jurisdiction review. A full release with pending scope must fail. These tests demonstrate accountability enforcement; semantic review still determines whether fictional mechanics faithfully adapt the research.
