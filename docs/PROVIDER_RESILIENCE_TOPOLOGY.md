# Paid Provider resilience topology

This bounded topology supports the Provider adaptations of `progress.goal.ln` (second site connected) and `progress.goal.rd` (same-case service through an incident). It does not itself qualify either goal or create incident, call, route-sample, or settlement evidence. The sequence assessor is a separate module.

The canonical service graph has two tenant-scoped sites: a head office and a service branch. The initial paid `primary-upstream` operation commissions one 20 Mbps path. Identity and the inbound carrier bind at the head office; service, the existing desk endpoint, and room bind at the branch. Other endpoint resources are included only when the Provider-owned resource hook proves they existed at installation. A later paid endpoint remains unbound until a scoped `upstream-binding-extension` operation attaches it to the branch. The extension adds no site, link, Mbps, seat, or customer capital.

`diverse-upstream` or the earned `managed-diverse-upstream` alternative adds one 20 Mbps path between the same sites in a distinct failure domain. The topology helper assigns stable resource and domain IDs from the Provider customer ID, uses fixed authored configurations, and sets physical-transport setup and recurring invoices to zero. The parent Provider project and treasury own the authored commercial terms, so this helper cannot bill the child again.

The helper requires a validated paid-project/posting hook before producing transport commands. It records an install-time marker containing the actual project/posting, child clock, object generations, and bindings. Restore validation reconstructs configurations from the operation ID and customer scope, checks project receipts and provisioning due times, verifies actual pending/effective generations, and rejects unowned links, sites, bindings, transport invoices, and unverified domain changes. An absent marker remains valid for legacy Provider roots only when they have no resilience projects or transport graph. Unknown marker versions fail closed.

The inspector is a pure projection of actual transport state. It reports desired, provisioning, effective, and observed status separately, with Mbps capacity, occupied/remaining Kbps, latency, failure domains, direct primary/diverse availability, and the selected route. It does not claim that calls admitted before the transport installation used the new path. Later paid endpoints may remain valid but unbound until their separate binding extension is funded.

The fictional operation offers use these versioned authored cent amounts: `primary-upstream` 48,000 cents setup plus 5,000 cents per period (8 minutes, one engineer, one support); `diverse-upstream` 32,000 cents plus 7,000 cents per period (8 minutes, one engineer, one support); `managed-diverse-upstream` 16,000 cents plus 11,000 cents per period (10 minutes, no engineer, one support); `upstream-binding-extension` 8,000 cents once (3 minutes, one engineer, no support). These synthetic balances describe the campaign, not real carrier prices or service assurances.

The helper's tests use the real `SOC_TRANSPORT` command and provisioning domain to check paid authority, the two-path topology, failover selection, independent capacity, endpoint binding extension, early-effective forgery, altered capacity, extra objects, unknown versions, and transport-ledger non-duplication. Full public Provider incident/repair/call-sequence behavior, progression claims, visible controls, and deployment acceptance remain owned by other integration work.
