# CPaaS channel delivery webhooks

Source obligation: `uc-new:domain:cpaas-workflows` (`REQ-9af2d006b2b32f47`). This bounded slice models a callback generated by an accepted synthetic digital-channel delivery. It does not claim complete CPaaS API or workflow coverage.

`SOC_CHANNELS.recordDelivery` creates one callback job tied to the channel receipt, interaction, tenant, participant, channel, and case. Its idempotency key is derived from the receipt ID. Duplicate delivery recording returns the existing receipt and cannot enqueue another callback. Jobs run only when the shared synthetic clock advances; they never use HTTP or real credentials.

Callback policy has desired, effective, provisioning, generation and observed state. It defaults disabled to preserve existing channel behavior. A policy edit becomes effective on the next synthetic minute. Application authentication/availability and channel-supplier availability are independent observed fields. Authentication rejection fails immediately as `APP_AUTH_REJECTED`. Application downtime, supplier downtime, and receiver `RATE_LIMITED` responses retry up to the effective retry count with capped exponential backoff. Each attempt records its time, result, and next retry time. Exhausted jobs remain inspectable as failed; changing observations only affects future attempts and does not revive terminal jobs. The bounded history fails closed at capacity rather than silently evicting callback lineage.

Runtime API:

- `create({clock})` initializes the default callback policy and empty delivery log.
- `command(state, {action:'webhook-configure', config})` changes desired `{enabled,rateLimit,retries,backoff}`. `webhook-observe` changes observed `{authenticated,applicationAvailable,supplierAvailable}` without changing policy.
- `advance(state, clock)` makes due attempts in stable delivery order and applies no more than the configured rate limit per synthetic minute.
- `inspect(state).webhooks` returns desired/effective policy, generation, provisioning, observations and a copy of attempts. `validate` checks each callback against its exact channel receipt and acceptance, including tenant/person/channel/case/idempotency key. The configuration fingerprint excludes delivery attempts so ordinary execution does not invalidate configuration-bound evidence. `source()` includes the state machine.
- Legacy channel saves without `webhooks` still validate. An explicit channel command or clock advance initializes the field on the caller's dispatch clone.
