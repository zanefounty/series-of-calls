# WP-CHANNELS — individual permissions and distinct digital channels

Source obligations: `uc-new:domain:messages`, `uc-new:domain:cpaas-workflows`, `uc-new:domain:journeys`. This expands the workflow-level consent and single fictional channel in the existing operations pack. It does not assert real channel policies or pricing.

Implement optional `soc-channels-1`, state `s.channels`, factory `socChannelsKernel`, export `SOC_CHANNELS`, file `src/game/47-channels.js`. Parent owns kernel and console integration. Module owns `tests/channels.test.js` (AC-SOC-072–078) and `spec/work-packages/channels-handoff.md` only.

Three fictional profiles must have distinct executable rules: Chatterleaf Business (approved sender, per-person permission, finite reply window, approved out-of-window template); Letterbox Service (verified sender, permission appropriate to transactional/promotional purpose, asynchronous delivery, no invented universal reply-window restriction); Casechat Web (authenticated visitor session with expiry, inbound session handoff, no unsolicited outside-session outbound message). Every field is fictional scenario data. Delivery/read/resolution remain distinct.

Accounts have desired configuration, generation-staged provisioning, effective configuration and observed authentication/provider status. Contact permissions key by tenant, canonical person, channel and purpose, with explicit grant/revoke and expiry. An inbound window belongs to that tenant/person/channel/case, never to every case with a similar label. Revocation must be rechecked before dispatch/acceptance; it cannot undo already delivered data. A provider outage must not silently revoke consent or move data to another channel.

Commands: start, configure account, observe provider fault/recovery, record permission, open inbound conversation, pause/resume conversation, record read receipt. Inputs bounded and validated; state validates unique IDs, foreign keys, tenant binding and legal state transitions. An active Casechat session authenticates a canonical synthetic identity, not an arbitrary visitor-supplied cross-customer case ID. Paused async conversations hold no voice sessions or agent work; resume must recheck permission and identity.

Expose `eligibility(s, interaction, context)` as a pure result with account, tenant, channel, purpose, case, person, template/window decisions and explicit reason. Parent supplies binding from real core resources/case identity. Expose `beforeAccept` (pure current check) so existing operations retries cannot accept a revoked permission from an old snapshot. Existing operations still owns HTTP-like jobs/retries/idempotency and usage metering; never meter twice. Provide integration instructions showing how a message selects account/purpose/template and keeps old saves valid. Do not silently start this pack on old exercises.

Tests: positive and negative cases for each distinct channel, cross-person/case/tenant isolation, expired/revoked permission after queued retry, pause/resume with no resource allocation, read-before-delivery and duplicate read receipts, staged failed account configuration preserving prior effective state, bounded save validation, pure inspect and serialized factory equivalence. Tests must call actual policies rather than asserting file presence. Keep transient receipt/conversation progression out of configuration fingerprints.
