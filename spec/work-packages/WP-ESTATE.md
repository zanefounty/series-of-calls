# WP-ESTATE — specialist discovery, provisioning and controlled information movement

Sources: `uc-new:domain:discovery`, `provisioning`, `migration`, `identity`, `information-lineage`, `sovereignty`, `product-evidence`; applicable specialist ecosystem actors. Own `src/game/48-estate.js`, `tests/estate-operations.test.js`, optional `src/game/89-estate-ui.js`, and `spec/work-packages/estate-handoff.md`. Use `SOC_ESTATE`, factory `socEstateKernel`, optional `s.estate`, version `soc-estate-1`.

Discovery imports a bounded synthetic inventory of users, numbers, devices, sites and dependencies. Keep observed identifiers separate from canonical identities; record confidence, conflicts and unknowns. Repeated imports reconcile by stable source key without multiplying assets. Discovery cannot provision or approve an unknown relationship merely by finding it.

Connectors declare exact supported actions and resource kinds, auth/delegation, version and reachability. JML jobs snapshot requested changes, prerequisite identity links and per-item generation. Submit → pending → provision/blocked/partial/complete; recheck authority and generation at execution. Batch changes can partly fail, retain item-level reasons, and retry only failed items after recovery. Each successful item applies once. A leaver must remove entitlement and number/device access; a mover must not overwrite a newer independent edit. Recovery is explicit, not a blanket restore of all state.

Device projects track firmware/platform compatibility, scheduled maintenance, per-device result and rollback checkpoint. A firmware version does not imply a compatible native meeting mode. Preserve service during a staged cohort only where a compatible remaining device exists. Use the same central validated configure path through a parent-supplied hook rather than mutating arbitrary resource fields unvalidated.

Information movement supports explicit synthetic export/backup jobs. Evaluate record access/hold/deletion, destination region, administrator region, key custody and connected/local dependencies independently. Carry immutable lineage and permission narrowing to exported/backup metadata; forbid an index or backup from leaking data that the current policy would deny. A configured destination or product label alone is not a jurisdiction approval. Document where parent information policy supplies accepted constraints.

Acceptance IDs 059–064: discovery conflict/idempotency; connector capability/authority; partial JML with once-only retry; stale mover/leaver effects; device upgrade/rollback incompatibility; independent export/backup/admin/key boundaries and save/worker equivalence. Use fictional specialist names and relevant original-style comparisons. Leave real-vendor or legal assertions out of runtime data. Parent integrates and audits your code before registering evidence.
