# Funded service withdrawal

Provider can withdraw completed room, distributor-room, integrator-room, recording and transcription projects through a revision-bound quote on the selected project. The quote names affected live work, overlapping paid services and product dependencies. Unsupported or conflicting projects refuse before configuration changes.

Withdrawal disables only the authored resource at the next simulation minute. Room withdrawal fails an actual active meeting; recording withdrawal releases held capture and preserves the conversation's measured outcome; processor withdrawal blocks retained-input jobs until eligible processing returns. It does not invent a failed conversation or delete captured history.

Repeated withdrawal and paid recommissioning retain each generation. An archive storage obligation transfers to the new paid recording project on completion, so withdrawing it again does not duplicate the archive fee. Transfer receipts reference that actual funded project; transferring storage does not claim the records were deleted.

Setup remains spent. The original recurring supplier commitment runs through its quoted minimum. Recording withdrawal retains the archive and charges A$30 per period after that minimum while stored records remain. Settlement uses cumulative integer-cent exposure. Customer exit quotes separately disclose continuing retained storage, which survives exit. The quote discloses these costs before commitment.

Restoring service requires a new paid project, ordinary staff and delivery time. The project records the actual resource generations submitted through dispatch. Restore rejects a resource re-enabled without a later funded generation. Old failures remain recorded; renewed delivery requires new actual work.

`tests/provider-service-retirement-dispatch.test.js` exercises actual room interruption and replacement, capture interruption and retained storage, blocked transcription and resumed input, pending save/worker continuation, once-only requests, stale quotes and forged retirement scope/cost/version. Pure-helper and UI tests additionally verify dependency refusal and the contextual controls. These checks do not close the wider gameplay acceptance ledger or certify all product-family lifecycle behavior.
