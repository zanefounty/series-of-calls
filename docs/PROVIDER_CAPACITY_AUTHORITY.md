# Provider capacity authority

`SOC_PROVIDER_CAPACITY_AUTHORITY.validateCustomer(providerCampaign, customer, childRoot)` is a pure restore check. Call it after the Provider campaign has validated the customer-to-portfolio link, paid project and posting lineage, project recipes, and deployment generations. It does not create historical evidence or accept a mutable cached digest.

The helper starts from the typed resource defaults (including the disabled Provider starting people count), applies each submitted and non-cancelled paid project in `configSubmittedAt` order, and resolves each patch from the versioned stage plan, operation definition, product recipe, or Government architecture. It also includes the fixed five-message rate limit applied by paid API and programmable-engagement commissioning. A ready resource must have the derived target effective. While it is provisioning, the effective value may be the target or the immediately preceding funded target; a still older value is not accepted after a later reset. Carrier and capture headroom receipts must be the exact authored four-unit increment; BPO cover must match its paid project and fixed provider-cover people; a later authored config replaces the earlier limit instead of inheriting a lifetime maximum.

Covered fields are explicit: `phone.capacity`, `carrier.capacity`, `people.people`, `people.entitlements`, `people.handlingMinutes`, `people.digitalConcurrency`, `service.capacity`, `service.maxWait`, `queue.capacity`, `queue.maxWait`, `messages.rateLimit`, `recorder.capacity`, `archive.capacity`, `archive.retentionDays`, and `speech.capacity`. The helper covers stage plans, recording/transcription, carrier/capture headroom, BPO cover, product recipe resource patches, Government architecture patches, and capacity changes made by funded mitigation.

Their units follow the resource schemas: phone seats; carrier concurrent sessions; people and entitlements as people/seats; handling and wait values as simulation minutes; workforce concurrency as simultaneous digital work per person; queue capacity as concurrent queue cases; channel rate as messages per period; recorder capacity as concurrent capture reservations; archive capacity as GB and retention as days; and speech capacity as processor-minutes per period.

Provider restore now has a separate meeting-admission check for `information.meeting.capacity` and its incident/repair lineage. Workforce roster/licence consistency, room and queue reservations, channel delivery rate, processor reservations, and products' typed feature units still need their own domain checks. This helper does not claim those checks; it does not authorize arbitrary resource imports or Lab configuration. New capacity-changing mechanics must add a versioned source patch and a behavioural test here before they become Provider-authorized.
