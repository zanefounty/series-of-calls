# Provider paid scale observation

This pack defines paid, customer scoped workload offers around the existing native `tb` service observer. It keeps the `progress.goal.tb` thresholds unchanged: ten sampled minutes, twelve successful human journeys, at least 90% completion across every in-window intended-service attempt, eight completion buckets, two named people, and three samples with at least two concurrent assignments.

`paid-scale-baseline` funds a measurement of the existing ordinary service without changing its configuration. The initial service uses three minute handling plus one minute wrap; a baseline bought after a workflow change measures that changed service. It is an honest measurement that may fail. `paid-scale-workflow` separately prices a one minute, consented short task, zero wrap, one provider engineer/support allocation and requires the existing paid BPO capacity. `managed-scale-workflow` becomes eligible only after the TB milestone and trades lower setup/engineering cost for a longer lead and higher recurring charge. Neither workflow operation grants staff. Commissioning changes the paid service handling minimum to one minute and wrap to zero; ordinary authored call durations remain unchanged, so a three-minute ordinary voice call still takes at least three minutes. The effective service configuration and BPO roster must come from paid Provider records, and workflow commissioning must be refused without them. Root integration owns verification of the earned TB receipt.

The pack is deliberately a separate run ledger. It must never add scale tasks to `providerCampaign.jobs` or change the 24 due ordinary cases per campaign period. One paid run opens one native observer window. The workflow's authored schedule creates twelve actual one-minute voice tasks across offsets 0–8, with paired tasks at offsets 0, 1 and 2 to establish sampled concurrency. The baseline creates no paid tasks. The observer is authoritative for arrivals, attempts, journeys, samples and result. The run reconciler retains every observer attempt, including ordinary campaign attempts; no attempt may be filtered to improve the completion ratio. Every attempt is joined to its source job, real case, interaction and actual person/assignment where one exists. Missing lineage makes the run invalid.

## Integration contract

The Provider integration uses `SOC.provider.quote`, paid `provider/operation` orders and the explicit `provider/start-scale-window { projectId }` command through validated dispatch. The pure module exports operation terms and planning, start, minute reconciliation, finalization/evaluation, validation and retention pins. Its hooks must:

- verify active tenant ownership, paid project and central posting, paid BPO capacity, effective short-task configuration and provider staff;
- for `managed-scale-workflow`, verify earned TB using the Provider campaign's authoritative receipt; the module's `earnedTbAt` hook is only a quote/eligibility fact;
- open `serviceObservation` with its existing `open-window { goal: "tb" }` command after project commissioning;
- let the ordinary child minute lifecycle advance the observer exactly once; this module must not advance time or call native `advance` itself;
- call `emitDue` before the child minute for its current clock; its `interact` hook must use the real validated interaction command and return the created case and interaction IDs; use ordinary cases, actual consent and real workforce assignments;
- let `advance` run after the existing child minute and native observation advance; its `interaction`, `usage` and `postUsage` hooks must read the actual interaction, derive billed usage from its native usage record, and post that exact amount through the central ledger once using the paid task ID as an idempotency key; the Provider adapter should use reason `provider-scale-voice-usage`, quantity equal to actual `usageMinutes`, and the authored per-minute voice price;
- implement `validateUsagePosting` as a read-only check against the central ledger and validate every open as well as closed run against its current native window, paid project, emitted task interactions, usage and posting records; and
- resolve each native observer interaction to its true ordinary-job or paid-scale-job origin, including case, agent, assignment and usage charges.

Only the paid workflow may schedule authored short tasks. The scheduler must be time aligned with observer sampling, bounded by the run window and paid capacity, and must not issue duplicate jobs. Emission is idempotent within an offset, including refused tasks. A paid project and its central posting can fund one observation window only; a second run needs a new paid purchase. Each started task records its actual case and interaction; completed/failed tasks retain their actual agent, workforce assignment and usage posting. Usage and operation charges go through the central business ledger. Failed attempts and failed windows remain visible; a retry is a new paid run with its own native window.

The commissioned project retains the consumed run and native window IDs. Restore checks both directions: each run must match that project marker, and each native TB window opened after paid scale commissioning must belong to exactly one run. Deleting a summary, recalculating its pins or removing the whole sidecar cannot free that paid project for reuse. Accepted task commands retain the authored channel, caller, destination, tenant scope, language and duration; schedule, start and finish timestamps must agree with the native interaction.

The retained state is optional and version 1. `pins()` reports run, project, posting, observer window, job, case and interaction IDs needed to keep the underlying evidence available. The run cap is 20, matching the native observer's 30-window cap while leaving room for other observer goals. Per-run attempt retention is capped at the native observer's 400 attempts. Old saves without this field remain valid; the root includes worker serialization, validates the optional sidecar on restore and preserves its case, interaction, assignment and ordinary-job evidence through history compaction. Unknown sidecar versions are rejected.
