# WP-CALLING — calling policy and shared services

Sources: `uc-new:domain:directory-dialplan`, `identity`, `signalling`, `media`, `emergency`, `continuity`; `uc-new:family:cisco:dedicated-premises` and Microsoft workplace-phone. This package implements narrower mechanics, not full product parity.

Own `src/game/50-calling.js`, `tests/calling-policy.test.js`, optional `src/game/93-calling-ui.js`, and `spec/work-packages/calling-handoff.md`. Use `SOC_CALLING`, factory `socCallingKernel`, optional state `s.calling`, version `soc-calling-1`. Read core interfaces before coding.

Provide versioned schemas for directory/tenant policy, shared routing services, media policy and emergency policy. Support configure with per-node provisioning and old-effective preservation on dependency failure. Keep JSON command validation bounded and strict. Parent dispatch will expose `{type:'calling',command}` and enforce business delegation.

1. Directory maps canonical identities and endpoints to tenants, aliases to dialled targets, and explicit directed federation edges. Same short extension in different tenants is not ambiguous within one tenant; an unqualified cross-tenant match must not leak. Public-number reach and internal federation are separate permissions. IDs must resolve, invalid maps fail clearly, and caller context stays stable.
2. Ordered forwarding and configured fallback have explicit triggers (unregistered/unavailable/capacity). Detect loops and bound traversal. A prohibited route must never become permitted by fallback. Reception groups select a registered member deterministically, respecting tenant and availability constraints, then a configured mailbox if no member can answer. Do not convert member count into session capacity.
3. Voicemail is a synthetic artefact with owner, mailbox capacity, archive availability, creation/retention and source interaction. A stored message is not a human conversation resolution. Reading requires the mailbox owner or declared delegate. Unavailable/full storage is a distinct outcome. Never prune a parent still referenced by information lineage.
4. Media inspection separately reports codec compatibility, encryption requirement, NAT/reachability in both directions, latency, jitter and loss. Signalling success must remain visible when media fails. Thresholds are declared fictional scenario values. No bandwidth-to-seats or bandwidth-to-agents conversion.
5. Synthetic emergency tests use an explicit `test-emergency` intent rather than a live dialler. Require a known caller, validated site/location in the exercise jurisdiction, explicitly eligible emergency route, reachable carrier/local dependencies and configured notifications. Ordinary calling permission must not establish emergency eligibility. No real emergency call or claim of legal compliance.

Suggested parent hooks: normalise(s, raw, caller); extensionCandidates(s, caller, resources); resolve(s,i,target,services,emit) returning target or terminal result; media(s,i,emit) returning failure code or null; emergency(s,i,services,emit) returning null when not applicable or an explicit outcome; command/advance/validate/inspect/fingerprint/source. Document exact final signatures and where terminal voicemail processing occurs so the parent does not duplicate recording or billing.

Acceptance IDs 045–052: tenant/alias/federation, forwarding loop/permission, fallback trigger, deterministic group/voicemail ownership, full/unavailable mailbox, media failure after signalling, emergency eligibility/location/notification, save/worker/pure inspection. Tests may exercise the module directly with real core fixtures; parent adds integrated journeys. Use original-style fictional humour in names/flavour and explain what was transposed.
