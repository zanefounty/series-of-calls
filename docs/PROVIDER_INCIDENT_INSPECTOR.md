# Provider incident inspector

The selected customer's incident inspector now shows the affected customer and friendly service name, current observed availability and reasons, and a bounded sample of recent failed work. It does not treat an empty recent sample as proof that no work failed.

Cause confidence distinguishes a recorded incident event from an undiagnosed cause. Confirmation requires the retained incident receipt to identify the same resource, or a nonempty matching transport failure domain, at the validated activation phase. Reading the inspector performs no diagnosis, changes no state and consumes no time. This change adds no paid diagnosis operation and does not close that separate scenario obligation.

Repair, mitigation and service-repair choices use current customer-scoped engine quotes; transport faults use the transport-repair choice. The comparison discloses setup, recurring cost, minimum commitment and term, implementation effort, any separately quoted commissioning delay, shared staffing, cash after commitment and available usage rates. Missing quote terms are identified as unavailable. Implementation effort is not represented as guaranteed service restoration time. Acknowledgement, insufficient funds and staffing blockers explain the next available step; the blocked quote remains reviewable while its commitment stays subject to the existing dispatcher.

The pure renderer is `src/game/93-ui/79-provider-incidents.js`, mounted from the existing customer inspector. It sends only existing acknowledgement and operation-quote control attributes. It does not bypass quote revision, payment, staffing, provisioning or incident resolution rules. The recent-journey section also mounts the separately implemented execution and billing-unit explanation.
